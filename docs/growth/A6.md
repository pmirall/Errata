# RECON A6

## Lo que ya existe
**The status is ONE BIT plus ONE u32 DEADLINE, and nothing else.**

STATE. `BugInstance.status` bit `PBS_CORRUPTED 0x04` (`Errata/src/persistence/save_schema.h:116`) and `BugInstance.corrupt_until_epoch` (u32, **offset 114**, `save_schema.h:185`), carved out of the old `reserved[12]`. `reserved[8]` survives at offset 118 (`save_schema.h:186`), and the layout is pinned by `static_assert`s at `save_schema.h:194-205`. `validate_bug()` checks `status` against `VLD_STATUS_MASK` (`Errata/src/game/validate.cpp:29,152`) and **does not check `BugInstance.reserved[]` for zero at all** — the only reserved-must-be-zero rule in that file is `CustomSpeciesRec` (`validate.cpp:342-343`). Not on the wire: `BUGW_STATUS_MASK` is `PBS_SICK|PBS_ASLEEP` only (`Errata/src/networking/protocol.h:338`, rationale `:335-336`).

API — six functions, one pure TU (`Errata/src/game/corruption.cpp`, 93 lines, no Arduino/RNG/float):
- `cor_apply(p, now, cal)` — sets bit + deadline `now + CORRUPT_DURATION_S`, saturating (`corruption.cpp:31-33`). **REFRESHES, NEVER STACKS** (`:37-38`): a second corruption only pushes the deadline out. Refuses on `CAL_UNSET` (`:19-22,26`).
- `cor_expire(p, now, cal)` — clears bit AND deadline once due, all-or-nothing (`:53-57`).
- `cor_clear(p)` — the Antivirus route, no clock (`:61-68`).
- `cor_service(slots, n, now, cal)` — the whole-Box walk (`:70-81`).
- `cor_is_corrupted(p)` — reads the BIT, not the deadline (`:83-86`).
- `cor_left_s(p, now, cal)` (`:88-93`).

CALLERS (exhaustive, `Errata/src` only):
- ARM: `ui/screen_encounter.cpp:558`, on `SPEV_CORRUPTION`. Only writer in the tree.
- CURE: `game/inventory.cpp:138`, item 7 Antivirus, `clears:["SICK","CORRUPTED"]` (`tools/content/items.json` id 7).
- EXPIRE: `app/app.cpp:1110`, 1 Hz, whole Box, gated on `!gs_readonly()`, saves on any expiry (`app.cpp:1089-1112`).
- READ: `ui/ui.cpp:2591` (`BugView.corrupted`), `ui/ui.cpp:2596-2599` (`cor_left_s` → `BugView.corrupt_h`, rounded up, capped 255), `ui/pet_view.cpp:181` (`PetView.corrupted`), `game/battle.cpp:402`, `app/app.cpp:406-407` and `game/inventory.cpp:188-190` and `dev/diag_core.cpp:590-593` (EvoContext).

Behaviour row is one `PF_TEMPER` row, re-derived on the EDGE at `petfx.cpp:873`.

EVOLUTION. `EVOC_CORRUPTED` (`Errata/src/data/evolution_table.h:39`), exactly two rows: `{11,12,20,EVOC_CORRUPTED,1}` Artefax→Burnix (`:63`) and `{47,48,20,EVOC_CORRUPTED,1}` Errox→Panika (`:87`). **`evolution.cpp:50-52` ignores `cond_value` entirely** — it returns `ctx.corrupted != 0`, while both JSON rows carry `"cond_value": 1` (`tools/content/evolution.json:76,316`). Nothing gates that.

## Riesgos
- THE PROSE IS THE FAILURE MODE, NOT THE PIXELS. docs/manual/content/guide.typ says '*Corrupto.* Dura 24 h y se pasa solo' (:277-278), 'Corruption is not a fault and food does not fix it' (:288-291), 'un suceso especial puede dejar a tu Bug corrupto durante 24 h' (:640,:655), and the glossary 'un estado que dura 24~h' (:1251,:1271). An axis makes all six false and NO GATE CATCHES ONE OF THEM - this is exactly the LUZ failure CLAUDE.md names, where a deleted menu row stayed in the manual for months. The guide agent is not optional here.
- cor_expire() changing from 'clear' to 'decay and re-arm' alters what cor_service()'s return value means to app/app.cpp:1110. Today non-zero triggers gs_save_active(true). With decay it fires up to CORRUPT_MAX_LEVEL times per Bug over three days instead of once - correct, but it is a new write cadence on NVS. The save is already rate-limited inside save_manager, so this is a flag rather than a defect; measure it, do not assume it.
- A benched Bug now takes up to 3 x 24 h to clean instead of 24 h. That is the feature, and it is also a real change to how long an Antivirus is worth having. balance.json's CORRUPTION._doc calls corruption 'a signature mechanic, not an annoyance'; at max_level 3 with severity 1 per encounter and HIDDEN networks at 30 % weight for event 4 (specials.json WEIGHTS), a player exploring hidden networks daily could sit at level 3 indefinitely. verify.py section 14 checks the event fires at least WEEKLY but has no upper bound - add one, or the axis becomes a ratchet.
- Widening EvoContext.corrupted from a boolean to a level silently changes dev/diag_core.cpp:590-593 and game/inventory.cpp:188-190 as well as app/app.cpp:406. evolution.cpp's default arm (`:61-67`) refuses unknown conditions, which is right, but a fill site left at 0/1 while the rule asks for >= 2 makes an evolution unreachable with no test failing unless the new verify.py bound exists.
- The glitch at level 3 must stay legible as corruption rather than as a broken panel. corrupt_fx.cpp:61-66 already caps rows by span_y so a 2 px body cannot repeat a row and XOR itself away; a higher CFX_ROWS_MAX interacts with that. tests/tools/corrupt_view.cpp (tests/Makefile:1016-1019, `make corrupttool`) is the tool for looking at it - use it, because no golden can tell you whether an effect READS as corruption.
- tests/golden/battle_v1.txt and the lockstep hash are one careless line away. Touching battle_stat_eff() (battle.cpp:141-146) or battle_init() (:402) re-records that transcript, bumps BATTLE_ENGINE_VER past 3, and breaks test_corruption.cpp:743's literal CHECK_EQ. That is why battle is cut, and it is the thing a reviewer will ask for.

Shipping an axis without it widens the gap between what the pack documents and what the firmware does - and the pack is what docs/index.html is generated from. Either the doc string is amended in this commit or the divergence gets louder.
- docs/budget.md section 16 is two commits stale (1,354,812 / 59,468 against the live 1,364,250 / 61,276). Anyone sizing this change off that table believes there are 5,532 B of globals free when there are 3,724.
