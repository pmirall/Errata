## Lo que ya existe
THE PIPELINE, END TO END.

1. THE ONE LOOP WHERE A NAME AND AN ADDRESS EXIST is `scan_read()` in `Errata/src/networking/net.cpp:750-785`. Per access point it builds a `NetFacts` (four bytes, `net_classify.h:55-61`):
   - `f.auth = auth_of(rec->authmode)` (net.cpp:769) — the project enum `NAUTH_OPEN/WEP/PSK/ENTERPRISE/OWE/OTHER` (`data/network_table.h:56-64`), mapped from `wifi_auth_mode_t` by the one function allowed to name it (net.cpp:680-699) and pinned by four static_asserts (net.cpp:702-708).
   - `f.hidden = (name_len == 0)` (net.cpp:770).
   - `f.rssi = net_rssi_clamp(rec->rssi)` (net.cpp:771, clamp at net_classify.cpp:23-27).
   - `f.tokens = net_tokens_of(rec->ssid, name_len)` (net.cpp:772-773) — a 3-bit `NTOK_VENUE|NTOK_ISP_CPE|NTOK_OPERATOR` mask (`network_table.h:67-70`), produced by splitting the name into ASCII-letter runs, FNV-1a-hashing runs of >= `NET_TOKEN_MIN_LEN` 3 letters and binary-searching an 88-row sorted table (net_classify.cpp:86-126). The stack buffer is zeroed on exit (net_classify.cpp:122-124).

2. WHAT SURVIVES THAT LOOP is `ScanResult`, 8 B (`networking/wifi_scanner.h:63-69`): `net_hash` (salted FNV of the six BSSID bytes, `net_classify.cpp:44-58`, with 0 folded to `NET_HASH_NEVER_ZERO`), `rssi`, `category`, and `reserved[2]` which net.cpp writes as literal 0 (net.cpp:778-779).

3. WHAT IS COMPUTED AND THEN DISCARDED, exactly: `f.auth` (3 bits of information) and `f.tokens` (3 bits). Both are consumed only by `net_classify()` (net_classify.cpp:132-175) and collapse into one of six ordinals. `f.hidden` is recoverable (`category == NET_CAT_HIDDEN`); `f.rssi` survives. So the scanner throws away ~6 bits per network that it has already paid to compute. Concretely: a locked network with a VENUE token and a locked network at -50 dBm with no token are both PUBLIC/HOME with no trace of which rung answered (net_classify.cpp:155-169); ENTERPRISE and a strong PSK both reach BUSINESS by different rungs and are indistinguishable downstream.

4. `NET_RSSI_NEAR` (-55) and `NET_RSSI_MID` (-75) (`network_table.h:80-81`, from `tools/content/networks.json`) are read in exactly one place — the WEP/PSK branch (net_classify.cpp:160-168). The OPEN/OWE, ENTERPRISE and hidden rungs never consult signal at all.

5. THE ROLL. `ui/screen_network.cpp:69-166` (`hand_off`) walks `s_job.res[]`, hands the WHOLE array's hashes to `act_note_networks()` first (screen_network.cpp:105-111), computes `bonus_pm` from the day's activity score (:116), then takes the FIRST network that is off cooldown (:118-121) and fills an `EncounterInput` (:124-137). `encounter_roll()` (`game/encounters.cpp:196-264`) seeds FNV-1a over net_hash, bucket, device_seed, category, rssi, active_level, progress (`encounters.cpp:41-57`), draws one independent per-stage value (`stage_draw`, :87-95, tagged 0x01-0x06 — the fix for a measured conditioning bug, :59-77), picks a row by weight (:109-123), and — only for a WILD row — applies the P6-C2 rare promotion to the next rarity band up in the same category (:164-175, :216-221). `rare_bonus_pm` is deliberately absent from the seed (:51-55).
   `EncounterInput.rssi` is documented as "part of the seed, never part of the weights" (`encounters.h:100`), and `progress` as tuning nothing (:102-104). `rare_bonus_pm` is the only field that moves a weight (:105-123).

6. THE COOLDOWN TABLE stores, per network, exactly `{uint32_t net_hash; uint32_t until_epoch;}` — 8 B, `persistence/save_schema.h:433-437`. The 272 B blob is `magic/version/n/seq/act_day/act_score/rows[32]/reserved_b[2]/crc16` (:439-449) with five offsetof static_asserts (:451-458). The only unspent bytes in the whole blob are `reserved_b[2]` — two bytes for the table, not per row. A per-boot RAM mirror of 32 `{hash, until_ms}` rows lives in `game/cooldowns.cpp:13-18` and costs 257 B of globals (budget.md §3 nm table).

7. A DEAD BYTE ALREADY EXISTS: `ui/screen_encounter.cpp:32` declares `static uint8_t s_cat`, `:470` writes it in `encounter_arm()`, and nothing ever reads it (grep over screen_encounter.{h,cpp} returns those two lines only). The category reaches the encounter screen and is discarded a second time.
