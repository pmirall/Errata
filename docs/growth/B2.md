# RECON B2

## Lo que ya existe
**net_hash — what it is.** A salted FNV-1a 32 of the six BSSID bytes plus a per-device salt, computed inside `net_hash_from_bssid()` (`Errata/src/networking/net_classify.cpp:44-58`). The salt is `net_scan_salt(device_id)` = FNV-1a 32 of the literal `"pbl-scan"` followed by device_id little-endian (`net_classify.cpp:29-42`). Zero is folded to `NET_HASH_NEVER_ZERO` 0x50424C4E (`net_classify.h:145`) because 0 is `CooldownRow`'s empty-row marker. The name is deliberately NOT folded in (`net_classify.h:126-135`): a hidden network reveals its SSID on a later scan and a renamed router keeps its address, so hashing the name would give one AP two identities. Consequences that bound this feature: a phone hotspot with MAC randomisation is a NEW place every scan and nothing can fix that (`net_classify.h:132-135`); a factory wipe regenerates device_id, so every stored hash goes stale at once (`net_classify.h:141-143`).

**Where a hash is allowed to exist.** `ScanResult` is 8 B — `net_hash` u32, `rssi` i8, `category` u8, `reserved[2]` (`networking/wifi_scanner.h:64-70`). No SSID, no BSSID, no channel, no auth mode anywhere downstream; `tools/check.sh` greps that header for both forbidden words and gate 3 requires every assignment to `reserved[2]` under `src/networking` to be a literal zero (`wifi_scanner.h:56-62`).

**CooldownTable layout, exactly.** 272 B, keys `cd0`/`cd1` (pair) — `persistence/save_schema.h:439-459`:
`magic` u16 @0, `version` u8 @2, `n` u8 @3, `seq` u32 @4, `act_day` u16 @8, `act_score` u16 @10, `rows[32]` @12, `reserved_b[2]` @268, `crc16` @270. `CooldownRow` is `{u32 net_hash; u32 until_epoch;}`, 8 B, both words fully used (`save_schema.h:433-437`). **The only spare bytes in this blob are `reserved_b[2]` — two.** The four that used to be `reserved_a[4]` were spent on the activity day bucket at P6-C2 (`save_schema.h:389-396`).

**What `game/cooldowns.cpp` does with rows.** `cd_ready()` and `cd_arm()` only, both taking the table by reference (`game/cooldowns.h:96,119`). `cd_arm()` writes `until_epoch = now + ENCOUNTER_COOLDOWN_S` (7200, `core/config.h:520`) into `slot_for()`'s pick: own row, else an empty one, else **the smallest deadline — which with one fixed period is LRU and expired-first in one rule** (`cooldowns.cpp:62-71`, argued at `cooldowns.h:104-109`). `recount()` rewrites `n`. There is a second, per-boot RAM table of the same width used whenever `cal == CAL_UNSET`, and `promote()` moves live RAM rows into the persisted table the moment the clock becomes trustworthy (`cooldowns.cpp:101-119`). `cd_take_dirty()` is take-and-clear because `cd_ready()` can dirty the table too (`cooldowns.h:121-128`).

**Nothing records a first-seen time or a count. Anywhere.** The only per-network persisted fact in the entire tree is `until_epoch`, and it is a *deadline*, not a history: it is overwritten on every re-arm and the row is evicted when 32 are full. The one distinct-network counter that exists — `s_net[ACT_CAP_NETS]` in `game/activity.cpp:47`, 10 u32s — is explicitly per-boot `.bss`, cleared by `act_begin()` (`activity.cpp:88-96`), and its whole design note says an eleventh entry could never change an answer because the day's term is capped at 10 (`activity.cpp:16-21`). **So the cooldown table forgets, and the activity set forgets harder.** A diary cannot be derived from either; it has to be its own store.

**Where a row would be written from.** `hand_off()` in `ui/screen_network.cpp:69-166`. The whole scan goes to `act_note_networks()` first (`:102-111`), then the loop takes the FIRST network off cooldown, rolls the encounter, calls `cd_arm()` and `ui_explore_commit()` (`:146-147`) and returns. So **at most one network per scan is "explored"** — that is the natural diary cadence, and it already carries `r.category` at that point.

**Free space, measured.** `ConfigV2` is 256 B; `dex[15]` sits at 102 and `reserved[152 - DEX_BYTES]` = **137 bytes at offset 117** (`save_schema.h:314`). That is the tree's one large reserve and the header says so (`save_schema.h:417-421`). Everything else: `CooldownTable.reserved_b[2]`, `BoxHeader.reserved[4]`, `BugInstance.reserved[8]` (per-bug), `PendingTrade.reserved[2]`, `CustomSpeciesRec.reserved[17]` (per-slot). Nothing else is big enough.

**The precedent this feature is a copy of.** P10-C8's wiki: `game/dex.{h,cpp}` owns only bit arithmetic over bytes the caller owns (`game/dex.h:20-30`), bound once at `persistence/game_state.cpp:246` (`dex_bind(s_gs.cfg.dex)`), carved from the front of `reserved[]` with **no schema bump** because zeros are the correct starting state (`save_schema.h:306-313`). Measured cost of that whole feature — module + screen + menu row + 15 persisted bytes + three call sites: **+2,356 B flash, +128 B globals** (`CHANGELOG.md:308-309`).

**The budget, as the repo last measured it.** `CHANGELOG.md:308-309` gives release **1,363,996 / 1,600,000 flash and 61,276 / 65,000 globals** at P10-C8 → 3,724 B of globals free. That is exactly the brief's number. `docs/budget.md:1202-1203` still prints 1,354,812 / 59,468 (245,188 / 5,532 free) — **stale by three commits**, the same defect §16's own warning box describes. Caps are `core/config.h:698-699`.

## La costura
**Storage (zero new globals):** `uint8_t places[PLACE_BYTES]` carved from the FRONT of `ConfigV2.reserved`, `Errata/src/persistence/save_schema.h:314`, leaving `reserved[152 - DEX_BYTES - PLACE_BYTES]`. `PLACE_BYTES` / `PLACE_SLOTS` go in `core/nt_types.h` next to `DEX_BYTES` (`nt_types.h:425`) for the same stated reason: `persistence/` may not include a game header.

**RAW BYTES, NOT A STRUCT ARRAY — this is the trap.** `ConfigV2` sits at `GameState` offset 1312 (`save_schema.h:555-563`); `reserved` starts at 117, so absolute offset 1429 is **not 4-aligned**. Declaring a member containing a `uint32_t` there makes the compiler insert 3 bytes of padding, which moves `crc16` off 254 and blows `static_assert(sizeof(ConfigV2) == 256)` — or, worse, an unaligned u32 load on RV32. Pack and unpack the row bytes explicitly, the way `net_scan_salt()` writes its buffer (`networking/net_classify.cpp:36-41`).

**Logic:** new pure module `game/places.{h,cpp}`, shaped exactly on `game/dex.{h,cpp}`: `pl_bind(uint8_t*)`, `pl_unbind()`, `pl_reset()`, `pl_note(net_hash, category, day) -> bool changed`, `pl_count()`, `pl_row(i, PlaceView&)`, `pl_take_dirty()`. No file-scope state but a bound pointer and a dirty byte. Covered automatically by `tools/check.sh:631-635` (src/game must not include Arduino.h / u8g2 / gfx.h / render.h) and `tools/check.sh:2216` (no allocator in the pure layers).

**Bind:** one line after `dex_bind(s_gs.cfg.dex)` at `persistence/game_state.cpp:246`. The comment at `game_state.cpp:158-160` — "ConfigV2.dex is NOT written from the runtime Config and must not be" — has to name `places` too, because `cfg_to_v2()` is field-by-field (`game_state.cpp:133-161`) and the next person to add a `memcpy` there erases the diary.

**Write site:** `ui/screen_network.cpp:146`, one call beside `(void)cd_arm(...)`, guarded by `cal != CAL_UNSET` for the same reason `cd_arm()` refuses to persist there (`game/cooldowns.h:19-42`).

**Flush:** `ui_explore_commit()` in `ui/ui.cpp:2366-2400` writes `cds`, `inv` and Bug slots — **it does not write `cfg`**, so the diary would sit in RAM for ever. Add `const bool pl_dirty = pl_take_dirty(); if (pl_dirty) (void)save_config(gs.cfg);`. It must be its own `const bool` on its own line: `ui.cpp:2382-2388` already documents that `a() || b()` swallows a take-and-clear flag, and that comment exists because it happened.

**Screen:** `ui/screen_places.{h,cpp}` + `SCR_PLACES` appended to `ScreenId` **after `SCR_DIAG`** so no id renumbers (`core/nt_types.h:51-92`; `ui/screen_table.cpp:241-251` is the banner about exactly this). **Five guards fire on a new ScreenId** (CLAUDE.md says four was wrong): `dev/diag_core.cpp:678-691` `kScreenName[]`; the three counts at `ui/screen_table.cpp:249-251`; `kAudit[]` at `tests/test_screens.cpp:5195-5230`; and in `tests/test_statemachine.cpp` **both** `kExits[]` (~`:925-945`) and `kRender[]` (`:300-310`).

**Entry point:** a row under `AJUSTES` (`ui/screen_settings.h:15-16`, `SET_*` enum + `SET_ROWS`, dispatched at `screen_settings.cpp:107`). **Not** a 9th main-menu ring item — see the cuts.

## Riesgos
- **The alignment trap is the most likely way to get this wrong.** ConfigV2 starts at GameState+1312 and `reserved` at +117, so absolute 1429. Any member containing a uint32_t there gets 3 bytes of compiler padding, shifting crc16 off 254. The sizeof assert catches it — but only if you do not 'fix' it by shrinking reserved[] to compensate, which would silently move the CRC span.
- **A test that owns its own array proves nothing.** This is the house defect verbatim (CLAUDE.md, 'lo que se prueba no es lo que se envía'), and tests/test_dex.cpp:23 is the exact shape of it: every pl_* unit test keeps passing if pl_bind() is never called or is pointed at the wrong bytes. The reboot test is the only one that can fail on that, and it must be mutation-proved.
- **The diary in cfg has no save cadence of its own.** ui_explore_commit() writes cds/inv/bug slots only (ui.cpp:2387-2399). Without the new save_config() line the diary lives in RAM until some unrelated settings change flushes it — which is also true of the dex today and is a latent weakness this commit inherits rather than creates. Worth naming in the header.
- **The take-and-clear short-circuit.** `cd_take_dirty() || act_take_dirty()` would leave the second flag standing; ui.cpp:2382-2386 already documents that this happened. A third flag folded into that expression repeats it exactly.
- **Flash wear.** One explored network currently writes the 272 B cd pair; this adds the 256 B cfg pair on the same event, roughly doubling per-explore bytes. Bounded by one explore per scan (screen_network.cpp:63-67) and by SAVE_MIN_GAP_MS deferral, but it is a real change to the write profile and nothing measures wear on this device.
- **A factory wipe re-rolls device_id, so every stored net_hash goes stale** (net_classify.h:141-143). The diary will read as empty after a wipe even though the rows are still there. That is correct behaviour but it looks like data loss, so it belongs in the manual prose, not only in a header.
- **MAC randomisation.** A phone hotspot is a new place on every scan (net_classify.h:132-135). With 16 slots and oldest-first-seen retention, a player who walks past hotspots all day will not thrash the diary (new places are refused once full) — but with an LRU rule they would have, which is the second reason the eviction rule differs from cooldowns.cpp's.
- **32-bit collisions.** net_classify.h:137-139 puts 32 rows of 32-bit hashes at ~1.2e-7. At 16 diary rows it is lower still, and a collision reads as 'already been here' — one missing diary entry, in the player's disfavour, never corruption.
- **Spending 128 of the 137 remaining reserve bytes leaves 9.** After this commit there is no reserved-bytes escape hatch left anywhere in the schema except CooldownTable.reserved_b[2] and BoxHeader.reserved[4]. The next feature that needs persisted bytes pays a SAVE_SCHEMA_VERSION bump or 272 B of globals. Say this out loud in save_schema.h's §3 comment block, the way P6-C2 did.
- **The 3,724 figure is the LAST MEASURED one, not a current reading.** It comes from CHANGELOG.md:308-309 at P10-C8; at least two commits since (the audio volume work and P10-C10) recorded no globals number at all, and docs/budget.md:1202-1203 is three commits stale in the other direction. arduino-cli is installed here, so tools/build_matrix.sh can settle it before anything is spent.

## Alcance recomendado
**One commit: \"El diario de lugares\" — 16 places, first-seen date, and nothing else.**

A GOOD version is the wiki commit again, with the subject changed. `game/places.{h,cpp}` is a pure module that owns byte arithmetic over 128 bytes the caller owns, carved from the front of `ConfigV2.reserved` with no schema bump because zeros are exactly "you have been nowhere yet". `pl_bind()` runs on the line after `dex_bind()`. `pl_note()` is called once, beside `cd_arm()`, on the one network per scan that was actually explored — so the diary's cadence is the cooldown's cadence and there is no second policy to keep in step. One card-at-a-time screen on `screen_dex.cpp`'s pattern, reached from a row under AJUSTES. `ui_explore_commit()` gains one `const bool` and one `save_config()`.

The eviction rule is what makes it a diary rather than a second cooldown table, and it is the one place the code deliberately disagrees with `cooldowns.cpp`: full means **keep the oldest first-seen and refuse the new place**, not LRU. Write that in the header next to a pointer at `cooldowns.h:104-109`, because the two files will otherwise look like one of them is wrong.

**The tests that must fail when it is broken, and the mutation that proves each one:**

3. `the_diary_is_flushed_by_an_explore` — after the scan above, the cfg blob on the fake store holds the row. **Mutation: delete the `save_config()` line from ui_explore_commit(), or fold `pl_take_dirty()` into the existing `||`.** The second mutation is the one the codebase has already made once and is invisible to every other test.

**128 of 3,724 is 3.4 %.**

**The alternative costs 272 B and is on the wrong axis.** A new `pl0`/`pl1` blob pair would grow `GameState` by `sizeof(PlaceDiary)` — a 272 B blob is **+272 B of globals, 7.3 % of what is free** — plus 20 NVS entries (the measured budget is 226 of 504 usable, `docs/save_schema.md:266-280`; the "262" in `save_schema.h:308,338` is the plan's stale figure and that file says so itself), plus a second CRC, a second half-writable copy, rows in `state_defaults()`, `scan_foreign()` and `commit_all()` (`save_manager.cpp:662-720`), and **a new line in the `SAVE_BLOB_MAX` assert block** — `SAVE_BLOB_MAX` is `sizeof(CooldownTable)` = 272 and the three asserts at `save_manager.cpp:16-19` name only the four existing blobs, so a 288 B blob would overflow six stack buffers with nothing firing.
